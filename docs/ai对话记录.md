## 踩坑记录

1. **AI 首版对"循环删除缺陷"的结论不成立**：用 `[1,2,3,4,5,6]` 验证得到 `[1,3,5]`，看上去"正确"。原因是奇数元素隔开了偶数，被跳过的位置恰好由后续偶数补上。换成 `[2,4,6]` 后得到 `[4]`，才真正暴露漏删——**验证要构造能推翻结论的数据**，这也是本次复盘的核心结论。
2. **Python 3.14 的报错文案变了**：3.14 抛出的是 `cannot use 'tuple' as a set element (unhashable type: 'list')`，而不是旧版本的 `unhashable type: 'list'`。测试断言只匹配关键字 `unhashable`，避免锁死版本文案。
3. **集合输出顺序不稳定**：`A & B` 直接打印出现过 `{12, 6}` 与 `{6, 12}` 两种顺序。报告与测试一律用 `sorted()` 固定展示顺序。
4. **`src` 包导入路径**：直接 `python src/main.py` 时 `sys.path[0]` 是 `src/` 而非仓库根，`from src.task5_course_stats import ...` 会失败；在 `main.py` 与测试中显式把仓库根插入 `sys.path` 解决。
5. **`dict.fromkeys` 的版本前提**：字典保序是 Python 3.7+ 的特性，报告里注明前提，避免在旧环境误用。

# 需求澄清：列表、元组、集合实验

> 依据《Python 列表、元组、集合 实验实训指导书》整理，动手写代码前先把目标、输入、输出、规则、边界与验收标准写清。

## 1. 目标

用一份可运行、可测试的 Python 工程完成指导书的五个任务，并产出一份完整实验报告；不引入任何第三方库（指导书要求"无第三方库依赖"）。

## 2. 运行形态

- 单入口：`python src/main.py` 依次输出五个任务的结果；
- 测试：`python -m unittest discover -s tests -v`；
- 源码按任务拆模块，便于单独调用与断言。

## 3. 各任务输入与输出

### 任务1 切片删除

| 输入 | 输出 |
|---|---|
| `[0..9]`，`del ls1[::3]` | 剩余 `[1,2,4,5,7,8]` |
| `[0..9]`，`del ls2[1::3]` | 剩余 `[0,2,3,5,6,8,9]` |
| `[0..5]`，`del ls3[::-2]` | 剩余 `[0,2,4]` |
| `[1..6]`，循环删偶数 | 剩余 `[1,3,5]`，并解释是否存在缺陷 |

要求输出中必须同时含：预判值、实际值、删除前的索引集合、原因分析。

### 任务2 可哈希

| 输入对象 | 期望 |
|---|---|
| `(1,2,3)` | 成功加入集合 |
| `(1,[2,3])` | 报 `TypeError`，原因为内含不可哈希的 list |
| `[1,2]` | 报错，list 不可哈希 |
| `frozenset({1,2})` | 成功 |
| `{1,2}` | 报错，普通 set 不可哈希 |

另需给出"集合里放集合"的正确写法。

### 任务3 集合运算

输入 `A={2,4,6,8,10,12}`、`B={3,6,9,12,15}`，输出交集、并集、`A-B`、`B-A`、对称差；另用集合推导式输出 1~30 内 4 的倍数。

### 任务4 去重

输入 `data=[5,2,7,2,5,9,7,3,9,1]`，输出：
- 方案1 `list(set(data))` 的结果；
- 方案2 手写保序去重的结果；
- 拓展 `dict.fromkeys` 的结果。

另对 `nest=[[1,2],[3,4],[1,2],[5,6]]` 完成嵌套去重，输出 `[[1,2],[3,4],[5,6]]`。

### 任务5 综合统计

输入 `class1=[101,103,105,107,109,103,101]`、`class2=[102,104,106,108,109,107,102]`，输出五问：两班保序去重、交集、对称差、`1班-2班`、交集转元组，每步附文字说明。

## 4. 约束与规则

1. 只用标准库：`list`、`tuple`、`set`、`frozenset`、`dict`、`unittest`；
2. 所有函数为纯函数式行为：不修改传入的列表（嵌套去重另行返回新列表）；
3. 集合类输出的展示顺序统一用 `sorted()` 固定，避免因哈希随机化导致报告数值前后不一致；
4. 保序去重必须"保留第一次出现顺序"，不得用 `set` 顶替；
5. 报告需覆盖指导书第七节的报告结构与五道必答思考题。

## 5. 边界与异常

- 空列表切片删除：返回 `[]`，不抛异常；
- `del ls[::-1]`：删除全部元素，返回 `[]`；
- 空区间集合推导式：返回 `set()`；
- 空列表去重：返回 `[]`；
- 两班均为空：交集、对称差均为空，交集的元组为 `()`；
- 元组内含列表：不得"为了能放进集合"擅自转成字符串，需如实报错并解释。

## 6. 验收标准

1. `python src/main.py` 一次跑通，五个任务输出齐全，任务1 含预判/实际对照；
2. `unittest` 全部通过，且用例覆盖五个任务，含边界与异常（不少于 6 个边界/异常用例）；
3. 报告含预判对比表、循环删除缺陷的实证（含能暴露缺陷的数据）、五道思考题完整作答；
4. 仓库 README 说明运行方式与目录结构；
5. 工程可独立上传 GitHub，作为"一个实验 = 一个仓库"的独立项目。

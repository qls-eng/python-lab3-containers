# 复盘：列表、元组、集合实验

## 一、交给 AI 的环节

- 五个任务的模块拆分与函数骨架；
- `slice.indices()` 计算删除索引的写法；
- 可哈希探测的 `try/except TypeError` 包装；
- 三种去重方案与嵌套去重的实现；
- `unittest` 用例框架的搭建。

## 二、自己拍板的环节

1. **只依赖标准库**：指导书明确"无第三方库依赖"，因此测试用 `unittest` 而不是 pytest，不给仓库引入依赖文件。
2. **结果展示顺序统一 `sorted()`**：集合是无序的，若不固定展示顺序，报告里的数值会随运行漂移，无法复核。排序只影响展示，不影响集合运算本身。
3. **任务1 追加"连续偶数"对照实验**：指导书给的 `[1,2,3,4,5,6]` 跑出来是 `[1,3,5]`，看起来"正确"。我没有直接照抄结论，而是补了 `[2,4,6]`，得到 `[4]`，用数据证明缺陷存在。这是本次最有价值的一处判断。
4. **任务5 ① 必须保序**：没有用 `sorted(set(class1))` 图省事，因为题目要求"保序"，`sorted` 会改变原始出现顺序。
5. **报告结构严格按指导书第七节**：名称、目的、环境、原理、步骤、源码、运行结果、预判对比、思考题、小结，一节不缺。
6. **函数不修改入参**：`delete_by_slice`、`dedup_nested` 都返回新对象，避免报告中的示例互相污染。

## 三、人工风险审查

1. **切片删除结论是否可靠**：逐条核对删除索引与剩余元素，三组都与手算一致；负步长单独确认是"从末尾往前"取索引，而非从头部。
2. **循环删除的结论是否成立**：用两组数据对照，确认 `[1,2,3,4,5,6]` 的正确只是巧合，`[2,4,6]` 才暴露漏删；报告中如实写明"本次恰好删干净"，没有把巧合当正确。
3. **异常是否被吞掉**：`probe_hashable` 只捕获 `TypeError`，并保留原始错误文本，其他异常照常抛出，避免掩盖真实问题。
4. **测试断言是否稳固**：无序去重只断言"元素集合一致 + 长度"，不断言具体顺序；不可哈希只断言关键字 `unhashable`，不锁死 Python 版本文案。
5. **数据是否被污染**：嵌套去重与切片删除均有"原数据未被修改"的断言。
6. **报告数值一致性**：报告中的所有数值均来自 `docs/images/run_output.txt` 的实际运行输出，不是手写估计。
